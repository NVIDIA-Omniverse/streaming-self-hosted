# OVDC deployment script procedure

Read this from `SKILL.md` during script generation. Paths such as `references/`
are relative to the skill root, where the reviewed output script is written.
Assemble the steps in order; dispatch `--teardown` before install steps and
make `--test` opt-in. The main skill contains inputs, sizing and validation;
`references/test-and-verify.md` contains the optional runtime checks.


### Idempotency rule

Use existence checks that distinguish absence from an API/RBAC error.
Namespace, pull-secret and StorageClass creation must stop on lookup failure;
Helm and PodMonitoring use declarative reconciliation.

### Step 1 — Preflight checks

```bash
#!/bin/bash
set -euo pipefail
# Generated by: infra-as-doc / caches-ovdc-deploy skill
# Cluster: <CLUSTER_NAME>  Zone: <ZONE>  Namespace: <OVDC_NAMESPACE>
#
# Deploys OVDC as shader cache for Kit/write-render-worker.
# Produces Helm values override for write-render-worker extraCmdArgs.
#
# Usage:
#   ./ovdc-shader-cache.sh            # deploy OVDC + print Helm values
#   ./ovdc-shader-cache.sh --test     # also run proof-of-life Kit test
#   ./ovdc-shader-cache.sh --teardown # remove OVDC namespace

: "${CLUSTER_NAME:?Set CLUSTER_NAME}"
CACHE_PLATFORM="${CACHE_PLATFORM:-gke}"
case "$CACHE_PLATFORM" in
  gke|aks|eks|onprem) ;;
  *) echo "ERROR: CACHE_PLATFORM must be gke, aks, eks or onprem"; exit 1 ;;
esac
OVDC_NAMESPACE="${OVDC_NAMESPACE:-ovdc}"
NGC_SECRET_NAME="${NGC_SECRET_NAME:-ngc-secret}"
CACHE_STORAGE_MODE="${CACHE_STORAGE_MODE:-pvc}"
case "$CACHE_STORAGE_MODE" in
  pvc|ephemeral) ;;
  *) echo "ERROR: CACHE_STORAGE_MODE must be pvc or ephemeral"; exit 1 ;;
esac

# ZONE and gcloud/GCP_PROJECT_ID resolution are GKE-only. Other platforms
# use an already selected kubectl context; no cloud CLI is required on-prem.
if [ "$CACHE_PLATFORM" = "gke" ]; then
  : "${ZONE:?Set ZONE for CACHE_PLATFORM=gke}"

  # GCP_PROJECT_ID: prefer the project the kubectl context points at; the
  # user's gcloud default project may differ from the cluster's project,
  # and project-scoped operations (e.g. importing the Cloud Monitoring
  # dashboard) must target the cluster's project to see metrics. The GKE
  # context format is `gke_<project>_<zone>_<cluster>`; fall back to
  # `gcloud config` for non-GKE contexts.
  if [ -z "${GCP_PROJECT_ID:-}" ]; then
    ctx=$(kubectl config current-context 2>/dev/null)
    case "$ctx" in
      gke_*) GCP_PROJECT_ID=$(echo "$ctx" | cut -d_ -f2) ;;
      *)     GCP_PROJECT_ID=$(gcloud config get-value project 2>/dev/null) ;;
    esac
  fi
  gcloud_default=$(gcloud config get-value project 2>/dev/null)
  if [ -n "$gcloud_default" ] && [ "$gcloud_default" != "$GCP_PROJECT_ID" ]; then
    echo "WARN: gcloud default project ($gcloud_default) differs from cluster project ($GCP_PROJECT_ID)."
    echo "      Project-scoped commands (dashboards, IAM, logs) will use $GCP_PROJECT_ID."
  fi
fi

if ! kubectl cluster-info &>/dev/null; then
  echo "ERROR: kubectl cannot reach cluster. Run:"
  if [ "$CACHE_PLATFORM" = "gke" ]; then
    echo "  gcloud container clusters get-credentials $CLUSTER_NAME --location $ZONE --project $GCP_PROJECT_ID"
  elif [ "$CACHE_PLATFORM" = "aks" ]; then
    echo "  az aks get-credentials --resource-group <RESOURCE_GROUP> --name $CLUSTER_NAME"
  elif [ "$CACHE_PLATFORM" = "eks" ]; then
    echo "  aws eks update-kubeconfig --name $CLUSTER_NAME --region <REGION>"
  else
    echo "  Select the site's kubeconfig/context and verify cluster access."
  fi
  exit 1
fi
```

### Step 2 — Create namespace and NGC secret

```bash
set -euo pipefail
OVDC_NAMESPACE="${OVDC_NAMESPACE:-ovdc}"
NGC_SECRET_NAME="${NGC_SECRET_NAME:-ngc-secret}"
namespace_name=$(kubectl get namespace "$OVDC_NAMESPACE" --ignore-not-found -o name)
if [ -z "$namespace_name" ]; then
  kubectl create namespace "$OVDC_NAMESPACE"
fi

secret_name=$(kubectl get secret "$NGC_SECRET_NAME" -n "$OVDC_NAMESPACE" --ignore-not-found -o name)
if [ -z "$secret_name" ]; then
  # Secret material is sent only to the selected cluster's Secret API through
  # stdin, never to command arguments, disk, or an additional network endpoint.
  # Do not enable shell tracing while handling credentials.
  set +x
  : "${NGC_API_KEY:?Export a scoped NGC_API_KEY before creating the pull secret}"
  # Python \x24 produces a literal $ in the NVCR auth payload.
  NGC_SECRET_NAME="$NGC_SECRET_NAME" OVDC_NAMESPACE="$OVDC_NAMESPACE" python3 << 'PYEOF' | kubectl apply -f -
import json, base64, os
name = os.environ["NGC_SECRET_NAME"]
ns = os.environ["OVDC_NAMESPACE"]
auth = base64.b64encode(b"\x24oauthtoken:" + os.environ["NGC_API_KEY"].encode()).decode()
cfg = base64.b64encode(json.dumps({"auths": {"nvcr.io": {"auth": auth}}}).encode()).decode()
print(f"""apiVersion: v1
kind: Secret
metadata:
  name: {name}
  namespace: {ns}
type: kubernetes.io/dockerconfigjson
data:
  .dockerconfigjson: {cfg}""")
PYEOF
fi
```

### Step 3 — Choose cache storage and create StorageClass

**AKS (`CACHE_PLATFORM=aks`):** the default profile creates or reuses
`ovdc-premium-v2` from `references/aks-premium-v2-storageclass.yaml`:
Premium SSD v2 with 4000 IOPS and 1000 MB/s, independent of its 600Gi capacity.
Check [Azure's Premium SSD v2 requirements](https://learn.microsoft.com/en-us/azure/aks/use-premium-v2-disks)
for region/zone support and verify the compute nodes' disk performance limits.
An existing class is reused without changing it; verify its parameters.
For a custom `OVDC_VALUES_FILE`, provision the class named in that file first;
the script does not create the default class or override the custom selection.

**EKS/on-prem:** use an existing StorageClass. EKS defaults to `gp3`;
on-prem requires `STORAGE_CLASS` and uses [on-prem values](ovdc-onprem-values.yaml).
The [EKS profile](ovdc-eks-values.yaml) is a reference for adapting cache
settings, not a prescribed on-prem storage or hardware configuration.
For EKS, verify the [EBS CSI prerequisites](https://docs.aws.amazon.com/eks/latest/userguide/ebs-csi.html):
standard EBS CSI uses `ebs.csi.aws.com`; EKS Auto Mode uses
`ebs.csi.eks.amazonaws.com`. Check provisioned IOPS/throughput and node limits.
The script does not create or alter EKS/on-prem StorageClasses.

For GKE c4/g2/g4 node pools, first check whether the selected node pool
has local ephemeral SSD. Ask whether the user wants ephemeral cache
storage for maximum speed; cache contents are lost on pod reschedule to a
different node, node recreate, or node-pool scale-down. If the user does
not choose ephemeral storage, default `STORAGE_CLASS` to `hyperdisk-balanced`.
Reuse the class when it exists; otherwise create the tuned class below. An
explicit custom `STORAGE_CLASS` must already exist. Verify the existing class's
performance settings before deployment.
With explicit `9600` IOPS and `2400Mi` throughput, the PVC does **not**
need to be 2TiB to reach maximum throughput; use a smaller size such as
`600Gi` by editing `storage.volume.size` in a copy of the reference file
(the bundled PVC reference retains the legacy 2048Gi workload capacity).

The PVC profiles set `settings.store.maxSize: 512G` to bound per-pod
compaction/GC work, with disk space left for overhead. Existing releases must
retain their current PVC class/size in custom values: PVCs cannot shrink and
StatefulSet volume-claim templates are immutable. Use a separate cache migration
when changing the storage layout.

```bash
set -euo pipefail
CACHE_PLATFORM="${CACHE_PLATFORM:-gke}"
CACHE_STORAGE_MODE="${CACHE_STORAGE_MODE:-pvc}"
if [ "$CACHE_PLATFORM" = "aks" ]; then
  if [ "$CACHE_STORAGE_MODE" != "pvc" ]; then
    echo "ERROR: the AKS reference supports PVC mode only."
    exit 1
  fi
  case "${OVDC_VALUES_FILE:-references/ovdc-aks-values.yaml}" in
    references/ovdc-aks-values.yaml|./references/ovdc-aks-values.yaml)
      storage_class_name=$(kubectl get storageclass ovdc-premium-v2 --ignore-not-found -o name)
      if [ -z "$storage_class_name" ]; then
        kubectl apply -f references/aks-premium-v2-storageclass.yaml
      fi
      ;;
  esac
elif [ "$CACHE_PLATFORM" = "eks" ] || [ "$CACHE_PLATFORM" = "onprem" ]; then
  if [ "$CACHE_STORAGE_MODE" != "pvc" ]; then
    echo "ERROR: the EKS/on-prem references support PVC mode only."
    exit 1
  fi
  if [ "$CACHE_PLATFORM" = "onprem" ]; then
    : "${STORAGE_CLASS:?Set STORAGE_CLASS to an existing site class}"
  else
    case "${OVDC_VALUES_FILE:-references/ovdc-eks-values.yaml}" in
      references/ovdc-eks-values.yaml|./references/ovdc-eks-values.yaml) STORAGE_CLASS="${STORAGE_CLASS:-gp3}" ;;
      *) : "${STORAGE_CLASS:?Set STORAGE_CLASS to the class chosen for custom EKS values}" ;;
    esac
  fi
  storage_class_name=$(kubectl get storageclass "$STORAGE_CLASS" --ignore-not-found -o name)
  if [ -z "$storage_class_name" ]; then
    echo "ERROR: StorageClass $STORAGE_CLASS does not exist; provision it first."
    exit 1
  fi
elif [ "$CACHE_PLATFORM" = "gke" ] && [ "$CACHE_STORAGE_MODE" = "pvc" ]; then
  STORAGE_CLASS="${STORAGE_CLASS:-hyperdisk-balanced}"
  storage_class_name=$(kubectl get storageclass "$STORAGE_CLASS" --ignore-not-found -o name)
  if [ -z "$storage_class_name" ]; then
    if [ "$STORAGE_CLASS" != "hyperdisk-balanced" ]; then
      echo "ERROR: custom StorageClass $STORAGE_CLASS does not exist; provision it first."
      exit 1
    fi
  kubectl apply -f - <<EOF
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: $STORAGE_CLASS
provisioner: pd.csi.storage.gke.io
parameters:
  type: hyperdisk-balanced
  provisioned-iops-on-create: "9600"
  provisioned-throughput-on-create: "2400Mi"
volumeBindingMode: WaitForFirstConsumer
allowVolumeExpansion: true
reclaimPolicy: Delete
EOF
  fi
fi
```

### Step 4 — Helm install

Install OVDC via the 6.0.1 chart, passing the reference values file that matches
the target platform (`CACHE_PLATFORM`) and cache storage mode. The chart generates the ConfigMap, StatefulSet,
and headless Service from the values file. The chart does not create a
ServiceMonitor; use the separate PodMonitoring step for GKE. Do not hand-roll those manifests.

```bash
set -euo pipefail
CACHES_HELM_REPO_NAME="${CACHES_HELM_REPO_NAME:-nvidia-omniverse}"
OVDC_CHART_VERSION="${OVDC_CHART_VERSION:-6.0.1}"
OVDC_IMAGE_REGISTRY="${OVDC_IMAGE_REGISTRY:-nvcr.io}"
OVDC_IMAGE_REPOSITORY="${OVDC_IMAGE_REPOSITORY:-nvidia/omniverse/ovderivedcache}"
OVDC_IMAGE_TAG="${OVDC_IMAGE_TAG:-6.0.1}"
OVDC_REPLICAS="${OVDC_REPLICAS:-1}"
OVDC_MEMORY_PROFILE="${OVDC_MEMORY_PROFILE:-}"

if [ "${CACHE_PLATFORM}" = "aks" ]; then
  if [ "${CACHE_STORAGE_MODE}" != "pvc" ]; then
    echo "ERROR: the AKS reference supports PVC mode only."
    exit 1
  fi
  # AKS: preserve the StorageClass selected by the default or custom values file.
  OVDC_VALUES_FILE="${OVDC_VALUES_FILE:-references/ovdc-aks-values.yaml}"
  HELM_STORAGE_ARGS=()
elif [ "${CACHE_PLATFORM}" = "eks" ] || [ "${CACHE_PLATFORM}" = "onprem" ]; then
  if [ "${CACHE_STORAGE_MODE}" != "pvc" ]; then
    echo "ERROR: the EKS/on-prem references support PVC mode only."
    exit 1
  fi
  OVDC_VALUES_FILE="${OVDC_VALUES_FILE:-references/ovdc-${CACHE_PLATFORM}-values.yaml}"
  : "${STORAGE_CLASS:?Choose and check STORAGE_CLASS in Step 3}"
  HELM_STORAGE_ARGS=(--set "storage.volume.storageClassName=${STORAGE_CLASS}")
elif [ "${CACHE_STORAGE_MODE}" = "ephemeral" ]; then
  OVDC_VALUES_FILE="${OVDC_VALUES_FILE:-references/ovdc-gcp-g4-no-pvc-values.yaml}"
  HELM_STORAGE_ARGS=()
else
  OVDC_VALUES_FILE="${OVDC_VALUES_FILE:-references/ovdc-gcp-g4-values.yaml}"
  HELM_STORAGE_ARGS=()
  if [ -n "${STORAGE_CLASS:-}" ]; then
    HELM_STORAGE_ARGS=(--set "storage.volume.storageClassName=${STORAGE_CLASS}")
  fi
fi

HELM_MEMORY_ARGS=()
case "${OVDC_MEMORY_PROFILE}" in
  16gb) HELM_MEMORY_ARGS=(-f references/ovdc-memory-16gb.yaml) ;;
  32gb) HELM_MEMORY_ARGS=(-f references/ovdc-memory-32gb.yaml) ;;
  64gb) HELM_MEMORY_ARGS=(-f references/ovdc-memory-64gb.yaml) ;;
  "") ;;
  *)
    echo "ERROR: OVDC_MEMORY_PROFILE must be empty, 16gb, 32gb, or 64gb (got '${OVDC_MEMORY_PROFILE}')"
    exit 1
    ;;
esac

helm repo update "${CACHES_HELM_REPO_NAME}" >/dev/null

helm upgrade --install ovdc "${CACHES_HELM_REPO_NAME}/ovderivedcache" \
  --version "${OVDC_CHART_VERSION}" \
  --namespace "${OVDC_NAMESPACE}" --wait --timeout 5m \
  -f "${OVDC_VALUES_FILE}" \
  "${HELM_MEMORY_ARGS[@]}" \
  --set "replicas=${OVDC_REPLICAS}" \
  --set "image.registry=${OVDC_IMAGE_REGISTRY}" \
  --set "image.repository=${OVDC_IMAGE_REPOSITORY}" \
  --set "image.overrideTag=true" \
  --set-string "image.tag=${OVDC_IMAGE_TAG}" \
  --set "image.pullSecrets[0].name=${NGC_SECRET_NAME}" \
  "${HELM_STORAGE_ARGS[@]}"
```

| Override | Why it stays as `--set` (not in the values file) |
|---|---|
| `replicas` | Per-deployment sizing decision |
| `image.registry` | Selected registry host from the repo source-registry configuration |
| `image.repository` | Selected repository path ending in `ovderivedcache` |
| `image.overrideTag` | Enable the explicit image tag instead of the chart appVersion |
| `image.tag` | Selected `ovdc.ovderivedcache` version from the repo manifest |
| `image.pullSecrets[0].name` | Default expects `regcred`; NGC deployments use `${NGC_SECRET_NAME}` |
| `storage.volume.storageClassName` | Cluster-specific StorageClass name (PVC mode only) |

### Step 5 — Deploy PodMonitoring for GKE Managed Prometheus

The chart exposes Prometheus metrics on container port `3051` at `/metrics`.
GKE Managed Prometheus scrapes these via a PodMonitoring CRD. The
6.x chart does not create a Prometheus Operator `ServiceMonitor`; this
step adds the GMP-native PodMonitoring. Use integer port (not named) — named ports can
silently fail with Managed Prometheus.

**AKS/EKS/on-prem: skipped.** `PodMonitoring` (`monitoring.googleapis.com`) is a GKE Managed Prometheus
CRD; configure the selected platform's Prometheus scraper separately. The
script gates the apply on `CACHE_PLATFORM=gke` **and** the CRD being present, so under
`set -euo pipefail` it is a clean no-op on other platforms instead of a fatal `kubectl apply` error.

```bash
set -euo pipefail
CACHE_PLATFORM="${CACHE_PLATFORM:-gke}"
# PodMonitoring is a GKE Managed Prometheus CRD (monitoring.googleapis.com); it is absent on
# AKS, where a different scraper must be configured. Gate on platform AND CRD presence
# so this step never aborts the script under `set -euo pipefail`.
if [ "$CACHE_PLATFORM" = "gke" ] && kubectl get crd podmonitorings.monitoring.googleapis.com &>/dev/null; then
  kubectl apply -f - <<EOF
apiVersion: monitoring.googleapis.com/v1
kind: PodMonitoring
metadata:
  name: ovdc
  namespace: $OVDC_NAMESPACE
spec:
  selector:
    matchLabels:
      ovdc: kvnode
  endpoints:
    - port: 3051
      interval: 15s
      path: /metrics
EOF
else
  echo "Skipping PodMonitoring (CACHE_PLATFORM=$CACHE_PLATFORM; GKE Managed Prometheus CRD not present)."
fi
```

Metric names are a runtime contract: fetch `/metrics` from the deployed
OVDC version before creating queries or dashboards. The DDCS 5.x `ddcs_m_*`
dashboard is retained only in the legacy skill; do not mechanically rename
those metric names to `ovdc_m_*`. Compare the discovered get/put and cache
hit/miss counters across cold and warm Kit runs.

### Step 6 — Print write-render-worker Helm values

After OVDC is deployed, the script MUST print the Helm values override that
configures Kit to use OVDC for shader caching. The values block, the
OVDC endpoint format, and the drivercachewrapper path rules are defined
in the **Client Integration** section below; the script just emits them
to stdout for the operator to copy into their Mega deployment config.

### Step 7 — Proof-of-life test (optional)

Only when `ENABLE_TEST=true` or `--test` flag is passed. Deploys a Kit pod (Isaac Sim) that connects to OVDC and validates the shader cache pipeline end-to-end. The full Kit launch command (including the GKE `/usr/local/nvidia/lib64` `ldconfig` fix, `warmupMode=1` invocation, pass/fail checks, and test-pod constraints) lives in `references/test-and-verify.md` under "Step 7 — Proof-of-life test". Preserve the Kit flags; apply the library-path fix only on GKE Container-Optimized OS and select GPU labels/taints for the target cluster.

### Note on persisting overrides

The OVDC values in `references/ovdc-overrides.yaml` must be present on every
`helm upgrade` of the simulation release. Prefer merging them into the same
Helm values artifact used for install and upgrade. If the reference file is
kept as a separate layer, pass it on every upgrade after OVCC proxy wiring.

### Step 8 — Teardown

When `--teardown` is passed:

```bash
set -euo pipefail
kubectl delete namespace "$OVDC_NAMESPACE" --wait=false
echo "OVDC namespace $OVDC_NAMESPACE deletion requested; wait for deletion before reusing it."
```
