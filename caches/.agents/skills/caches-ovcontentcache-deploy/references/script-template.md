
# OVCC Deploy Script Template

The generated `ovcc-deploy.sh` MUST follow this structure. Substitute backend-specific flags from the SKILL.md Backend Configuration Reference. Produce the script for human review before execution; SKILL.md's Outputs section governs where it is stored.

The chart is `ovcontentcache` (NGC catalog name) but the container image repository is `usd-content-cache` (4.0.x is a chart rename only). Pin the chart at `OVCC_CHART_VERSION=4.0.4`; do not set `image.tag` — the chart `appVersion` (3.0.1) pins the runtime.

## Step 1 — Preflight

```bash
#!/bin/bash
set -euo pipefail
# Generated by: caches-ovcontentcache-deploy skill
# Cluster: <CLUSTER_NAME>  Zone: <ZONE>
# StorageClass: <STORAGE_CLASS>  Replicas: <REPLICA_COUNT>
# Chart: ovcontentcache <OVCC_CHART_VERSION>  Backends: <list enabled backends>
#
# Prerequisites:
#   - kubectl configured for the target cluster
#   - helm v3 installed
#   - python3, openssl, curl on PATH
#   - NGC_API_KEY set in environment
#   - GCS_HMAC_ACCESS_KEY_ID and GCS_HMAC_SECRET_ACCESS_KEY set in environment (GCS backend only)
#     Provision HMAC keys from the GCS project that stores the simulation assets
#
# Usage:
#   ./ovcc-deploy.sh              # deploy OVCC
#   ./ovcc-deploy.sh --scale N    # change replica count to N
#   ./ovcc-deploy.sh --teardown   # remove OVCC and all secrets

for bin in kubectl helm python3 openssl curl; do
  command -v "${bin}" >/dev/null 2>&1 || { echo "ERROR: ${bin} is required but not installed."; exit 1; }
done

: "${CLUSTER_NAME:?Set CLUSTER_NAME before running}"
: "${ZONE:?Set ZONE before running}"
: "${NGC_API_KEY:?Set NGC_API_KEY before running}"
export NGC_API_KEY  # Python subprocesses need this

# CLOUD_PROVIDER determines which project-scoped helpers apply.
CLOUD_PROVIDER="${CLOUD_PROVIDER:-gke}"

# GCP_PROJECT_ID, CACHES_HELM_REPO, CACHES_HELM_REPO_NAME, and
# OVCC_IMAGE_REPOSITORY are resolved by the agent during the
# conversation phase and injected as literals above (or required from
# the environment). The script does not parse kubectl context or shell
# out to gcloud at runtime.
[ "$CLOUD_PROVIDER" = "gke" ] && : "${GCP_PROJECT_ID:?Set GCP_PROJECT_ID (cluster project) for GKE}"

REPLICA_COUNT="${REPLICA_COUNT:-1}"
OVCC_NAMESPACE="${OVCC_NAMESPACE:-ovcc}"
OVCC_IMAGE_REGISTRY="${OVCC_IMAGE_REGISTRY:-nvcr.io}"
OVCC_CHART_VERSION="${OVCC_CHART_VERSION:-4.0.4}"
PVC_SIZE_GI="${PVC_SIZE_GI:-2048}"
NGC_SECRET_NAME="${NGC_SECRET_NAME:-ngc-secret}"

: "${CACHES_HELM_REPO:?Set CACHES_HELM_REPO (e.g. https://helm.ngc.nvidia.com/nvidia/omniverse)}"
: "${CACHES_HELM_REPO_NAME:?Set CACHES_HELM_REPO_NAME (helm repo alias, e.g. storage-caches-stg)}"
: "${OVCC_IMAGE_REPOSITORY:?Set OVCC_IMAGE_REPOSITORY (resolved from CACHES_HELM_REPO by the generator; ends in /usd-content-cache)}"
# Chart path is ovcontentcache; image repository (OVCC_IMAGE_REPOSITORY) is usd-content-cache.
HELM_CHART_PATH="${HELM_CHART_PATH:-${CACHES_HELM_REPO_NAME}/ovcontentcache}"

: "${OVCC_VALUES_FILE:?Set OVCC_VALUES_FILE to the skill-local reference values file}"
[[ -f "${OVCC_VALUES_FILE}" ]] || { echo "ERROR: OVCC_VALUES_FILE not found: ${OVCC_VALUES_FILE}"; exit 1; }
```

Add HMAC checks only when GCS is an enabled backend:

```bash
: "${GCS_HMAC_ACCESS_KEY_ID:?Set GCS_HMAC_ACCESS_KEY_ID for GCS backend}"
: "${GCS_HMAC_SECRET_ACCESS_KEY:?Set GCS_HMAC_SECRET_ACCESS_KEY for GCS backend}"
```

Verify cluster connectivity:

```bash
kubectl cluster-info || { echo "ERROR: Cannot reach cluster. Run: gcloud container clusters get-credentials ${CLUSTER_NAME} --zone=${ZONE}"; exit 1; }
```

## Step 2 — StorageClass check

The reference values file pins `persistence.storageClassName` (e.g.
`hyperdisk-extreme` for g4). Only set `STORAGE_CLASS` when overriding
the file's pinned class — pick from `cloud-knowledge.md` > Cross-Cloud
Quick Reference > Storage class per cloud.

```bash
HELM_STORAGE_ARGS=()
if [ -n "${STORAGE_CLASS:-}" ]; then
  if ! kubectl get storageclass "${STORAGE_CLASS}" &>/dev/null; then
    echo "ERROR: StorageClass '${STORAGE_CLASS}' not found."
    echo "Create the StorageClass before running this script, or choose one that already exists."
    exit 1
  fi
  HELM_STORAGE_ARGS+=(--set "persistence.storageClassName=${STORAGE_CLASS}")
fi
```

## Step 3 — Namespace and secrets

```bash
kubectl create namespace "${OVCC_NAMESPACE}" --dry-run=client -o yaml | kubectl apply -f -

# Pipes the secret manifest to kubectl via stdin so no $ touches the shell.
# Python \x24 produces a literal $ in the auth payload.
OVCC_NAMESPACE="${OVCC_NAMESPACE}" NGC_SECRET_NAME="${NGC_SECRET_NAME}" python3 << 'PYEOF' | kubectl apply -f -
import json, base64, os
ns = os.environ["OVCC_NAMESPACE"]
name = os.environ.get("NGC_SECRET_NAME", "ngc-secret")
# NGC_API_KEY is a user-provided environment variable (never hardcoded).
# Validated in Step 1 preflight: ${NGC_API_KEY:?Set NGC_API_KEY before running}
auth = base64.b64encode(b"\x24oauthtoken:" + os.environ["NGC_API_KEY"].encode()).decode()
cfg = base64.b64encode(json.dumps({"auths": {"nvcr.io": {"auth": auth}}}).encode()).decode()
print(f"""apiVersion: v1
kind: Secret
metadata:
  name: {name}
  namespace: {ns}
type: kubernetes.io/dockerconfigjson
data:
  .dockerconfigjson: {cfg}""")
PYEOF

# Restrictive umask + unique temp dir keep private key material 0600/0700.
# Trap fires on every exit path so the key never lingers if openssl/kubectl fails.
(
  umask 077
  TLS_TMP_DIR="$(mktemp -d "./${OVCC_NAMESPACE}-tls-tmp.XXXXXX")"
  trap 'rm -rf "${TLS_TMP_DIR}"' EXIT
  openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout "${TLS_TMP_DIR}/ovcc-tls.key" -out "${TLS_TMP_DIR}/ovcc-tls.crt" \
    -subj "/CN=ovcc"
  kubectl create secret tls ovcc-tls \
    --key "${TLS_TMP_DIR}/ovcc-tls.key" --cert "${TLS_TMP_DIR}/ovcc-tls.crt" \
    --namespace="${OVCC_NAMESPACE}" \
    --dry-run=client -o yaml | kubectl apply -f -
)
```

Include only when GCS is an enabled backend:

```bash
kubectl create secret generic gcs-hmac-credentials \
  --namespace="${OVCC_NAMESPACE}" \
  --from-literal=AWS_ACCESS_KEY_ID="${GCS_HMAC_ACCESS_KEY_ID}" \
  --from-literal=AWS_SECRET_ACCESS_KEY="${GCS_HMAC_SECRET_ACCESS_KEY}" \
  --dry-run=client -o yaml | kubectl apply -f -
```

S3 and Azure do not require OVCC-side credential secrets.

## Step 4 — Helm install

Pass the reference values file with `-f`. The reference encodes the
backend toggles, persistence layout, node placement, anti-affinity, and
Prometheus exposition; reserve `--set` for values that genuinely vary per deployment (image org, image tag from the repo manifest, secret names, replica count, storage class, storage mode).

**Image path.** The chart constructs the full image as
`image.registry/image.repository:image.tag`. These fields must be set
**separately**. Putting the full path in `image.repository` alone
results in a doubled registry prefix (e.g. `nvcr.io/nvcr.io/...`). The
reference values files deliberately do NOT set `image.repository`; the
agent resolves it from `CACHES_HELM_REPO` during the conversation phase
and injects the literal as `OVCC_IMAGE_REPOSITORY` (which ends in
`/usd-content-cache`, not `/ovcontentcache`). Do NOT set `image.tag` —
the chart `appVersion` pins the runtime image.

```bash
helm repo update "${CACHES_HELM_REPO_NAME}" >/dev/null

helm install ovcc "${HELM_CHART_PATH}" \
  --version "${OVCC_CHART_VERSION}" \
  --namespace "${OVCC_NAMESPACE}" --wait --timeout 5m \
  -f "${OVCC_VALUES_FILE}" \
  --set replicaCount="${REPLICA_COUNT}" \
  --set image.registry="${OVCC_IMAGE_REGISTRY}" \
  --set image.repository="${OVCC_IMAGE_REPOSITORY}" \
  --set "image.pullSecrets[0].name=${NGC_SECRET_NAME}" \
  --set tls.secretName=ovcc-tls \
  "${HELM_STORAGE_ARGS[@]}"
```

| Override | Why it stays as `--set` (not in the values file) |
|---|---|
| `--version` | Pin the `ovcontentcache` chart at `OVCC_CHART_VERSION` (default `4.0.4`); the chart name does not exist before `4.0.3`. |
| `replicaCount` | Computed per deployment from the queue-depth formula |
| `image.registry` | Registry hostname (e.g. `nvcr.io`). Must be set separately from repository. |
| `image.repository` | Org + image path (`<org>/usd-content-cache`); resolved from `CACHES_HELM_REPO` at generation time and injected as `OVCC_IMAGE_REPOSITORY` so the same values file works for staging and production. |
| `image.pullSecrets[0].name` | Default expects a different secret; the script's secret is `${NGC_SECRET_NAME}`. |
| `tls.secretName` | Default is `ovcc-tls`; set explicitly so the script's self-signed secret is used. |
| `persistence.storageClassName` | Optional override of the pinned class in the reference values file. |

## Step 5 — Validation

The OVCC container is **distroless**. `kubectl exec` is not available.
Use pod status, logs, and an external curl pod for validation.

```bash
echo "--- Pod status ---"
kubectl get pods -n "${OVCC_NAMESPACE}" -l app.kubernetes.io/name=ovcontentcache

echo "--- PVC status ---"
kubectl get pvc -n "${OVCC_NAMESPACE}"

echo "--- OVCC logs (last 10 lines) ---"
for i in $(seq 0 $(( REPLICA_COUNT - 1 ))); do
  echo "ovcc-${i}:"
  kubectl logs "ovcc-${i}" -n "${OVCC_NAMESPACE}" --tail=10
  echo ""
done

echo "--- Health check (via port-forward) ---"
kubectl port-forward -n "${OVCC_NAMESPACE}" "ovcc-0" 13129:13129 9145:9145 &
PF_PID=$!
# Trap guards against early exit; explicit `|| true` keeps cleanup non-fatal under set -e.
trap 'kill "${PF_PID}" 2>/dev/null || true' EXIT
sleep 2
# Fail-fast flags prevent the validation step from hanging when port-forward is unhealthy.
curl -fsS --max-time 10 http://localhost:13129/healthz && echo ""
curl -fsS --max-time 10 http://localhost:9145/cache_metrics | head -5
kill "${PF_PID}" 2>/dev/null || true
trap - EXIT
```

Expected: all pods `Running`, PVCs `Bound`, logs show NGINX startup, healthz returns `200 healthy`.

## Step 6 — Scale (`--scale N`)

```bash
# Invoked as: ./ovcc-deploy.sh --scale N  ($1=--scale, $2=N)
NEW_REPLICA_COUNT="${2:?Usage: $0 --scale N}"
helm upgrade ovcc "${HELM_CHART_PATH}" \
  --version "${OVCC_CHART_VERSION}" \
  --namespace "${OVCC_NAMESPACE}" --reuse-values \
  --set replicaCount="${NEW_REPLICA_COUNT}" \
  --wait --timeout 5m
```

## Note on persisting overrides

The OVCC override file (`ovcc-overrides.yaml`) must be passed
to every `helm upgrade` of the simulation release. To avoid forgetting
it, consider storing it as a ConfigMap in the simulation namespace so
it can be pulled automatically. The orchestrating workflow is
responsible for this; this skill only produces the override file.

## Step 7 — Teardown (`--teardown`)

```bash
helm uninstall ovcc --namespace "${OVCC_NAMESPACE}" --wait --timeout 5m

kubectl delete secret "${NGC_SECRET_NAME}" ovcc-tls -n "${OVCC_NAMESPACE}" --ignore-not-found
kubectl delete secret gcs-hmac-credentials -n "${OVCC_NAMESPACE}" --ignore-not-found

kubectl delete pvc -l app.kubernetes.io/name=ovcontentcache -n "${OVCC_NAMESPACE}"

kubectl delete namespace "${OVCC_NAMESPACE}" --ignore-not-found
```
